# 五窗口离线识别实验

独立验证脚本，不接入现有任务、设备网关或窗口缓存，不连接远端、不发送输入。
使用现有 Pillow 和 Apple Vision，无新增依赖。需在有 Apple Vision 权限的 macOS
环境运行；OCR 系统错误记录为失败，不能用模拟识别代替。

```sh
conda run -n rustdesk-mcp python mcp/experiments/window_detection/verify.py \
  --images /tmp/wintest-095838 \
  --output /tmp/window-verification-new \
  --extended --cpu-ocr
```

`--images` 中放两张原图：第一张 `pc3.png`、第二张 `pc1.png`。脚本检查
`cases.json` 中的 SHA-256 和尺寸，避免拿错素材。原图与回放产物保留在本机，
不入库。`--output` 必须是新目录，避免覆盖旧证据。更换图片需另建人工标注的
manifest，使用 `--manifest` 指定。`--skip-baseline` 可仅测试原型。
`--cpu-ocr` 在本实验进程内为原型和对照算法统一使用 CPU-only Vision 请求，
避开本次遇到的加速后端错误；不修改共享 `vision.py` 文件。省略时使用现有
自动后端。复测结论见 [RESULTS.md](RESULTS.md)。

## 算法与验收

1. 复用色带提取作为候选来源，合并同一标题栏被文字分开的上下段。
2. 标题区域保留上下边距，使用本地 OCR 确认“梦幻西游”；漏读时改为局部
   裁剪及 1x/2x 有限重试。地图区域失败时最多尝试 2x/1x/3x。
3. 标题下方的地图区必须同时出现坐标结构和时钟/时辰文字。
   不依赖具体地图名、角色头像或任务状态。尚未实现游戏图标模板匹配。
4. 标题栏宽度用于普通窗口；明显截短的标题只证明可见宽度，采用其他候选
   宽度中位数作为临时尺寸先验。底边在约 4:3 的局部范围寻找像素边缘。
5. 右上角橙蓝条的相对位置作为附加诊断，不是硬性门槛，也不识别角色身份。
   不可见可能是遮挡或特征提取失败，不直接等同于检测到 RustDesk 面板。

原型不接收人工矩形、不接收期望数量，也没有“五个凑满”的逻辑。
人工矩形只用于输出后的独立一对一匹配：数量、左上角位置、四边最大误差
分别评估，当前预设容差为 8 px（包含人工标注及窗口边框的不确定性）。
这个容差是粗定位实验标准，不是精确点击验收标准。

输出 `report.json`（图片哈希、OCR 原文及裁剪区域、拒绝原因、矩形、耗时、
逐窗误差）与每组原型/旧算法标注图。青色为人工参考框，紫色为测量框，
橙色为含推测边界的框。原型出现异常或未通过定位/几何检查时退出码为 1；
旧算法仅作为对照，不影响原型退出码。
报告中的 `error` 必须一并检查：空结果的计数检查可能符合负例预期，但系统
异常不能视为识别成功。原型汇总和退出码始终将任何系统异常判为失败。

`--extended` 额外检查整图平移 (4,3) px、缩放至 97%、空白桌面、仅保留标题栏。
这属于原图派生扰动，不是额外独立真实样本，也未覆盖单窗口独立移动/缩放。

## 限制

- 两张图是开发样本，不能据此声称通用识别率、P95 延迟或运行稳定性。
- 被面板截断的右边界仍为 `estimated`，即使人工误差检查通过，也不能宣称完整
  几何已验证；所有输出固定 `input_authorized=false`。
- 这里只验证窗口存在和粗定位，不验证账号、可点击区域或任务能否启动。
- RustDesk 面板稍后自动隐藏：在线方案应等新帧重新测量右边界。本实验不
  伪造隐藏后的画面、不操作面板、不将两张不同桌面当成同一设备的时间序列。
- 仍依赖浅色标题色带和这组地图 HUD 结构；标题完全遮挡、深色主题、战斗
  布局、不同 DPI 等需要独立素材测试。

回归面：仅新增本实验目录，没有修改任何既有运行文件或运行路径。
