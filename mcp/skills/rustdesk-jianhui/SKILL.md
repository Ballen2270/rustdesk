# 剑会自动匹配

用户手动准备十个账号、两个五人队并进入房间。只控制 pc1 上两个房主窗口，默认每窗口本次完成十场，不论输赢。战斗自动操作由用户预先配置。本 skill 不组队、不领取奖励、不退出房间、不操作其他账号。

## 开始前

设计、安装或校准不等于开始匹配。用户明确说开始/试跑之后才运行 `--execute`。用户指定试跑场数时遵从；否则默认十场。

仓库：`/Users/yanjoy/codeWorkSpace/vscode/rustdesk`。解释器从仓库 `.mcp.json` 的 rustdesk.command 读取；当前是 `/opt/homebrew/Caskroom/miniconda/base/envs/rustdesk-mcp/bin/python`。

先阅读 [运行说明](references/operation.md)。脚本 `scripts/jianhui.py` 自己连接仓库配置的 MCP stdio 服务，使用 screenshot/click/keep_alive，不直接绕过 MCP 发送输入。局部 OCR 在本地 Apple Vision 完成，图像特征在本地 Pillow 计算；运行循环没有在线模型请求。模型只负责启动校准、报告和无法自动核对的异常。

用 RustDesk MCP 获取 pc1 当前截图和原生分辨率。确认两个窗口均是预期房主，无遮挡、尺寸固定；建立配置，窗口矩形必须只包含游戏内容，不含 Windows 标题栏。不可直接沿用 images 中截图坐标。依照 `assets/pc1.example.json` 填两个内容矩形、房主标题关键词、原生分辨率并设置 calibrated=true。配置放在本地运行目录，不提交账号数据。

房主不一定在第一位。校准时检查每队实际房主站位，分别在 windows 条目内配置 ready_slots，覆盖其他四个队员的准备标记；不要把右队站位直接套给左队。OCR 房主图标文字可能失真，房间标题和角色卡上的同名房主可联合确认身份。

开始运行前用脚本 inspect 检查两个当前窗口截图，确认房间标题识别、四个准备槽及按钮位置。可用 observe 方式短跑；它不发送鼠标点击。若当前窗口不在房间或识别规则不匹配，先调整校准，不强行匹配。

## 运行约定

- 两窗口独立计数；鼠标点击串行。禁止另一个 agent/MCP 会话同时输入 pc1；脚本锁仅约束本 skill 的其他脚本实例，不能拦截外部工具。
- 看到四个不同队员槽位的“准备”，并稳定识别房间和“天梯匹配”，才允许匹配。不能把战斗里的“准备中”算作房间准备。
- “每周任务”面板（房间内或匹配结束后弹出）用鼠标右键关闭；窗口未激活导致未关闭时，脚本自动先左键激活再右键一次，仍不关闭则暂停。没有弹窗也应正常继续。
- “所有人都已经准备……倒计时”弹窗是踢出警告：出现即点“开始匹配”；倒计时耗尽被踢出房间属于异常，暂停核对。
- 胜负结果自动关闭期间继续观察另一个窗口，不固定阻塞三十秒。房间与结算每秒巡检，匹配/战斗也保持短巡检；以实测完整双窗口循环耗时评估时序。
- 已确认的战斗状态没有时长上限，长时间战斗本身不是异常，不因此点击、重连或补记场次；持续监控另一队。任务总时限默认关闭，只有用户指定运行时长才使用 --minutes。识别失败和连接失败仍需核对，不能将其当作正常战斗无限忽略。
- 本次进入战斗后再看到胜负结果才记一场，同一结果去重。若漏过结果直接回房，脚本暂停该窗口，请根据日志/战斗历程核对；不可猜测加数后继续。
- 十场后不再开始下一局。无须为清理第十场结算继续点击。
- 匹配按钮点击后不自动盲重试；需要看到匹配/战斗状态确认。输入超时可能已送达，应暂停核对。
- 脚本保存状态、最近截图和事件；状态中包含待执行动作。崩溃重启不自动续跑，避免重复点击或重复计数。
- 实测自动战斗可能只显示“取消”和技能图标。使用顶部回合数字与右下角“取消”的组合识别；不要强制要求始终出现“法术／道具／防御”。
- 局部 OCR 不明确时放大回合区并回退全图 OCR；已经由 OCR 确认的战斗可用该窗口独立学习的顶部徽章与底部控件图像复核。图像特征只维持战斗等待，不触发匹配或计数，不在两窗口间共享。
- 准备字样带装饰符或置信度偏低时，联合检查字样背后的绿色背景；不能仅凭绿色判定准备，不能把“未准备／准备中”归一成“准备”。
- 未知画面持续二十秒后记录 warning，禁止输入并继续本地观察；重新识别后自动接续。未决点击超时、漏结算导致计数不明等仍暂停核对。
- 用户说停止：创建运行目录 STOP 文件，检查状态为 stopped；必要时对本脚本 PID 发 SIGTERM，不杀 bridge。正常完成不主动关闭远端游戏。

运行期间读取 state.json / events.jsonl，及时报告每窗口进度。可用 viewer.py 网页观察台实时或事后观察（只读，含本地模型状态、操作时序与前后截图，详见运行说明）。识别未知、掉线、布局变化或耗时过长时检查 latest-*.png，必要时暂停。不要为了省 token 让模型自行承担每秒轮询。

## 验证与限制

离线 inspect 可使用仓库 images 图片，无需连接 pc1。改代码后先跑 test_jianhui.py、test_viewer.py 与 replay.py，再用 mock_e2e.sh 走完整离线端到端（mock MCP 剧本驱动，不碰 pc1）。当前参考包含房间、匹配中、匹配成功过场、战斗、失败结果和每周任务。匹配成功过场可能没有可靠 OCR 标记，允许短暂 unknown，但不能用它计数。胜利结果使用共同的“胜负结果”标题识别，首次遇到仍需核对。实际窗口校准及连续实战可靠性需首次试跑验证，不能宣称离线通过即已稳定跑完十场。
