## 一、目标与非目标

**目标**:人准备素材(散文 workflow + 注意点 + 每屏节点图片),agent **离线**完成制作:
量签名 → 生成 skill → 离线验证 → 出报告;人审核后固化。制作期 agent **不连接设备、不发送
任何输入**——错误的上界是"报告不合格、返工",不存在真机事故面。

真机部分沿用现有 skill 的人工授权流程:人摆好窗口、人发起 observe/`--rounds 1`、人旁观,
agent 只负责事后读产物汇总。

**非目标**:不做 agent 自主探索(v2 的 live 模式,已放弃);不做无人值守运行;试跑不由
agent 自行发起;缺图缺描述的语义不猜(进 unsupported/open_question)。

### 梦幻西游技能制作的必需交付

所有梦幻西游游戏界面自动操作 skill 都必须交付**可执行的本地图片识别与操作脚本**，
不能只写 SKILL.md、图片流程或让 AI 逐帧看图点击。本文的“制作期全离线”约束制作时
不操作真机，不意味着省略运行器；用户说“先制作 skill”同样包含本地脚本和离线验证。

- 参考剑会、门派、秘境的实际实现，复用 `_framework` 的 Apple Vision 区域 OCR、
  必要放大/全图兜底、Pillow 图像特征与战斗锚点。每个活动自行定义状态签名、点击目标、
  计数和停止条件；共享框架尚未落地的能力不得只写声明而不提供可执行实现。
- 运行中的截图识别、巡检、状态迁移、计数和输入由本地脚本完成，点击/滚动通过
  RustDesk MCP。不调用在线 AI 做逐帧识别，不要求本地大语言模型；AI 负责素材分析、
  脚本制作、校准、启动、进度汇报和异常核对。
- 交付包含 `SKILL.md`、本地运行入口、配置示例、离线 inspect/replay 入口、逻辑测试、
  明确绑定 mock MCP 的端到端测试及验证报告。沿用 observe/execute、输入前新帧复核、
  pending 确认、未知画面禁输入、STOP、证据留存和设备互斥约定。
- 回放必须走真实运行识别管线，核对状态与点击目标，并验证参考图及实际计划支持的
  窗口尺寸。报告区分本地识别通过、mock 操作通过与真机试跑，不能把文档完整或图片
  人工看懂当成自动化实现完成。
- 缺少某界面的素材时，明确该分支未验证或不支持；不得用 AI 看图接管代替必需的
  本地识别实现。未授权的真机试跑仍不执行，制作阶段可完成全部离线工作。

## 二点五、启动期窗口定位:发现与身份分离(框架能力,每运行必做,运行期静态)

窗口大小/位置**跨会话**可能变(恒 4:3),单次执行期间不动,每次运行开始前先识别。定位拆两步:

1. **发现(rect)**:全屏截图 → OCR 锚集 → 反推内容矩形(不含标题栏);
2. **独立验证(防循环论证)**:用**未参与求解的锚点**复核 + 窗口边界检测 + 几何残差;
   4:3 只是候选筛选先验,不构成正确性证明;
3. **身份验证**:位置最近邻只给初值;身份由窗口内稳定标识(角色名,校准时录入配置)对照
   确认。**验不出 = 匿名窗口**:不启动、不继承该账号配置/计数(防两账号互换位置指反);
   一对一指派,缺失/多余候选 → 暂停列明;人工确认身份**只在本次运行内有效**(绑定设备+
   截图+rect),窗口变化即失效,不产生跨会话的"已确认"标志;
4. **锁定后运行**:识别与点击映射到该 rect;输入前廉价复查锁定锚,漂移 → 暂停(不重定位,
   unknown 策略是 warning+禁输入+继续观察,硬暂停来自 pending/状态超时/漂移);
5. **尺寸下限**:每 skill 用参考图标定的 OCR 可靠性下限(不拍通用数值);
6. **验收(M1b)**:量化定位误差与错误接受率;覆盖重排/多窗/干扰锚/降采样映射/DPI/黑边/
   遮挡/边缘裁切;锚集按各 skill"启动必需屏"声明(team 房间屏可能无 活动/排行)。

本机制同时服务三处,但**只共用几何原语,策略分开**(v3.1):运行启动用 profile 锚集+身份
配置;measure 面对的新 skill 尚无锚集,且素材含战斗/弹窗等非启动屏(可能没有角色名/启动
锚)——靠素材 manifest 指定目标窗口,自动定位失败允许人补标注 rect,**不为完成制作猜窗**;
真机校准由人截全屏、agent 量 rect 出配置。

## 三、活动形态拆分:个人 / 组队

形态层只规定控制对象与协同关系,不把剑会契约提升为"组队=这些":

| 维度 | solo(原型 mijing) | team(原型 jianhui 及未来) |
|---|---|---|
| 控制对象 | N 窗 = N 账号,各走同一 workflow DAG | 少数协同窗(人预先安排编队/房间) |
| 设备拓扑 | 每台电脑一个连接、一个屏幕；同设备多窗串行 | 由活动 spec 决定 |
| 故障传播 | 每窗独立暂停 | 任一窗硬暂停 → 同队联动暂停 |
| 规模 | 1..8 窗,loop budget ∝ 窗口数 | 由活动 spec 决定 |

留在活动 profile:房间态/匹配/准备槽/踢警/计场(剑会契约)、solo 的 advance_delay/stall。
配置 schema 三层:公共(topology)→ 形态层(仅上表)→ 活动层(逐 skill)。

## 四、creator skill 本体(`mhxy-skill-creator`,素材驱动薄版)

### 4.1 素材包(人的输入契约)

```
mcp/skills/<new>/intake/
  workflow.md       # 散文流程。每步一行:屏名 | 做什么 | 期望屏;末节写计数语义
  notes.md          # 注意点:异常屏与处理(哪个弹窗怎么关)、失败表现、哪些情况必须停
  images/<屏名>.png  # 每屏 1-2 张(第 2 张 <屏名>-2.png),全屏原生截图,不预裁剪
```

- **manifest**(`manifest.json`):图片 → 状态标签 → 目标窗口标识(多窗全屏截图必须指明量
  哪一扇;自动定位失败允许人标注 rect),记录图片尺寸/窗口布局/是否缩放;
- **缺图三分规则**(v3.1):必经屏/计数确认屏缺图 → 报告 **blocked**,不能获得"可试跑"
  结论;异常屏缺图 → 允许出草稿,但**文字注意事项 ≠ 运行时识别保护**(弹窗可能保留底层
  页面锚,分类器仍会把它识别成可操作的正常屏——报告须如实标注此缺口);声明范围外的
  可选分支 → unsupported,并约束其入口与后续行为;
- **非视觉语义不由图片提供**(v3.1):超时取值、自动迁移、循环条件、guard 由 workflow.md
  声明或模板默认,缺失 → 待补项——静态图推不出时序;
- 计数语义是语义裁判项,报告里单独标"待人确认";
- **素材原图不入库**(v3.1):全屏截图含其他窗口/账号信息,与 mijing 参考图同例——仓库只
  提交 manifest+哈希,intake 原图本机私有,固化命令不自动提交原图;
- 素材齐备性检查是 intake 的第一产出(缺什么列什么,人补齐再继续)。

### 4.2 制作流程(全离线,五阶段)

```
人① 提供素材包(workflow + notes + images)
 ↓  A intake     解析素材 → skill-spec 草稿 + 素材齐备性检查 + open_questions
 ↓  B measure    对每张图:定位裁窗(二点五)→ OCR → 签名候选 + 点击目标框;
                产出 measure.json(每屏的 OCR items 原文),供人抽查锚点是真是假
 ↓  C generate   spec+measure → screens/nodes/bookkeep 草稿/mock 剧本/replay 期望/
                SKILL.md;schema 表达不了的语义 → unsupported 清单,不猜
 ↓  D verify     单测模板 + replay(素材图回放)+ mock e2e + 轻量反例(4.4)
 ↓  E report     验证报告(4.5)
人② 审报告 → 调优 → 批准固化
```

**发布状态机**(v3.1 统一,取代"离线绿即固化"与"真机过才固化"的两套表述):
`草稿 → 离线验证通过 → 待人工试跑 → 批准发布`。离线草稿允许 commit 保存;**注册为可用
skill(symlink)的条件唯一** = 人工试跑通过 + 人批准;试跑结果回填**同一版本**的报告,
旧版本的试跑不能背书新版本发布。D 阶段验证入口**强制绑定 mock**:缺失或非法 mock 配置
立即失败,禁止回退 fleet——`session.load_spec` 缺省读仓库真实 `.mcp.json` 的回退行为在
creator 入口封死,离线边界由入口保证,不靠命令行自觉。之后任何变更重走验证阶梯。

### 4.3 measure(核心工具,inspect 的批量版)

输入素材图 → 按 manifest 定位裁窗(二点五)→ OCR(**记录每个 item 的来源 band/zoom**,与
运行时管线对齐)→ 对 workflow 声明的每步:
- 该屏签名候选:2-3 个锚(文本+归一化框+分数),取**特异、稳定**的(特异者优先:弹窗>菜单
  >面板>场景;艺术字易误读的用双词锚,参照 mijing"继续+挑战"先例);
- 该步**动作目标分型**(v3.1,不只 find_text):文本按钮 / **条目关联按钮**(列表内
  entry+button+search_box,复用 `find_row_button`)/ 固定区域 / 滚轮 / 右键。同屏多个候选
  且无法唯一消歧 → 输出 **unresolved,不自动选最高分**(最高置信度的"参加"可能属于另一
  活动行,而屏分类/交叉检查/同源 mock 都发现不了);
- 全部中间产物(OCR items 原文+来源)进 measure.json,并附**目标框叠加图**——人审的第
  一道抽查面(直接看选中了哪个控件)。

### 4.4 验证与轻量反例

三件套(replay/mock/单测)用同一批素材图,是同源测试,只证内部一致。轻量独立缓解:

- **分类+动作交叉检查**(v3.1 修正:不强求原始签名互斥——框架本就允许多签名命中、按声明
  顺序消歧,互斥要求会拒绝合法的分层识别):每张素材图的**最终分类**须等于其标注屏、所选
  动作符合 workflow 预期;同时报告签名重叠,确需互斥的状态对单独声明约束;
- **锚参与检查**(v3.1 修正:原"签名删锚后应失配"不可能成立——删锚只会放宽 AND 匹配):
  保持签名不变,从观测 OCR items 中**移除某必需锚的全部命中证据**,检查该匹配分支失效
  (any_of 需考虑其他分支是否仍合法命中)——验证的是条件确实参与匹配;
- **引用完整性**:所有 Node 的 source/expect 屏存在,每屏从启动屏沿 expect 边可达;
- **battle 正反例**:含战斗的 skill,battle_hits 对战斗图必中、对非战斗素材图必不中;
- **轻量扰动负例**(零真机):OCR 缺项、错词、同屏目标重复、pending 超时序列;
- replay **必须走生成 profile 的真实 recognize 路径**(bands/条件放大/fallback),不是独立
  简化管线——全图 zoom 里可读的锚,运行时未必扫得到;
- 上述不通过 → 回 C 调签名,不进真机。

真机验证回归人工阶梯:校准(人截全屏,agent 量 rect 出配置)→ observe 短跑(不发输入)→
人旁观 `--rounds 1` → 按发布状态机(4.2)批准。

### 4.5 验证报告(人审的唯一交接物)

- 素材清单与哈希(哪些屏有图/缺图、open_questions);
- measure 摘要:每屏签名候选与锚分数,**OCR items 原文附上**(人可核对锚是否真实存在);
- 生成物 diff(screens/nodes/bookkeep 草稿/**unsupported 清单**);
- 本地运行器与配置入口、识别/操作实现位置、在线模型调用检查及支持的窗口尺寸;
- checklist 红绿:三件套 + 交叉负例 + 锚删除 + battle 正反例;
- open_questions 终版(计数语义等待人确认项单列);
- 可追溯:素材版本、spec/profile 版本、`_framework` commit。

### 4.6 调优回路

- OCR 漂移 → 从素材图/新证据帧重量化签名(机械修改,人批 diff)→ 重走 replay+反例
  **及相关 mock 场景**(签名/band 变化会改变动作时序、pending 确认与计数路径,仅 replay 不足);
- 超时调整 → 重走带时 mock;
- 语义错误 → 改 bookkeep → 重走全阶梯;
- 全部修改经人批准后 commit。

## 六、风险与开放问题

1. **同源测试**:三件套与签名共用素材图,标错会被一起接受——缓解是分类+动作交叉检查、
   锚参与检查、目标框叠加图与 OCR 原文供人抽查,但**最终语义裁判是人**(计数对不对、某屏
   是否异常,日志看不出来);
2. **素材质量上限**:签名质量受限于素材图(艺术字误读、缺角度、缺异常屏)——measure.json
   让人看到 OCR 真实输出,判断该补图还是换锚;
3. **身份标识可靠性**:角色名艺术字 OCR 可能不稳,校准时录入并实测;不稳则该 skill 启动时
   身份映射需人确认——确认只在本次运行内有效(绑定设备+截图+rect),窗口变化即失效;
4. **定位误配**:干扰锚+几何错误可能骗过验证;缓解见二点五;最坏**通常**是 unknown/启动暂停,
   这是经验陈述不是保证;
5. jianhui 1x OCR 漂移(既存)M4 前不动;
6. creator 注册:`.claude/skills/mhxy-skill-creator` symlink,M2 完成时加入。
