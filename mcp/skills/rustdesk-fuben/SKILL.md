# 双客户端副本

用户预先组好两队；两个队长窗口可在同一设备或不同设备，队员设备由 `members` 单独配置。脚本驱动两个队长窗口按计划通关：**先侠士副本，再两个普通副本**；队长进入侠士等待界面时，自动扫各队员设备点"准备"。侠士次数：周一 3 次（首刷无侠义值，不影响计数），周二至周日 2 次；普通副本固定 2 个各 1 次。侠义值和奖励都不作为判断依据，只按通关次数计。

脚本 [scripts/fuben.py](scripts/fuben.py) 使用本机 Apple Vision OCR 与 Pillow，通过 RustDesk MCP 拟人点击/滚动。运行循环不调用在线模型；模型负责校准、启动、读进度和核对异常。

## 关键约定

- **队员准备是多设备自动的**（配置 `members` 设备列表，缺省空=回退手动；队员可与队长同设备——单连接四窗一屏布局即 `members:["pc1","pc2","pc3"]`，同设备队员无需 rect，全帧弹窗扫描天然覆盖）：侠士副本点"进入"后队长出现等待界面（队员侧是准备弹窗）。脚本对每个队员设备全帧 OCR，找"准备"按钮（规则：`准?/淮?` 读数 + 同行左侧有"拒绝"配对，弹窗成员列表的 未准备/已准备 行天然不配对，队长自己的等待界面也不会误配；小窗 615px 下按钮误读 淮备/准留 仍可配对），点击前新帧复核（倒计时掐死弹窗时绝不落点到城里）。与任一队长同设备的队员扫描在主循环内串行，其他独立设备由后台任务 sweep。倒计时被取消仍自动重新排队（`max_enter_retries` 上限内随机延迟重试，作为 sweep 失败的兜底）。
- **副本名每天轮换**：活动面板里定位文本含 `-普通` 的条目（同行的"参加"按钮必须存在；已完成的条目按钮变灰会被自然跳过），列表位置不固定，先上后下有界滚动搜索。两个 *-普通 条目都通向长安城百晓仙子，点哪个都行。
- **副本内循环**：任务面板出现"跳过剧情动画"就先点它；没有就点任务条目自动导航；到达后"请选择要做的事"对话框选项永远只有一个，点它进战斗；战斗只观察。三循环后出现收尾剧情（同样先点跳过）→ 奖励面板（"点击屏幕继续游戏"，奖励可能为空但有名字头像框）→ 点屏幕关闭 → 任务面板出现灰色"副本已完成"，点它回长安城。计数只认"副本已完成"（或回城后 60 秒宽限恢复）。
- **普通副本在面板里选最左的可用"进入"**：已通关的卡片按钮变"已通关"自然排除；两普通都完成后窗口目标达成。
- **周一第三次侠士**：按运行当天日期自动取 3/2，配置 `knight_runs` 或 `--knight N` 覆盖；`normal_runs` 默认 2。
- 所有点击/滚动经拟人随机偏移、多步鼠标轨迹、输入前新帧复核、pending 确认（队员准备点击同规）；未知画面 20 秒警告并禁输入；连续第二把侠士通常无需准备直接进，第三把必须重新准备——两种情况都已覆盖。

## 开始前

统一窗口清单、队长/账号选择和跨设备启动见 [统一启动](../STARTUP.md)。优先使用生成的目标配置；不含 `window_selection` 的旧配置仍按下述方式校准。不要为窗口位置、设备或轮数变化修改活动脚本。

先读 [运行说明](references/operation.md) 和 [图片流程](references/flow.md)（素材 1–24、26.png 在 `references/screens/`，原图在仓库 `images/副本/`）。每次启动脚本自动重新定位窗口（顶栏锚点吸附 + 标题栏像素兜底，配置 rect 仅尺寸提示，`autocal:false` 仅 mock 用），复制 [配置示例](assets/pc1.example.json) 填窗口尺寸/身份后设 `calibrated=true`。用户明确要求开始后才 `--execute`；先 observe 核对。执行从任意画面开始：中途遇到的已开副本会被收编继续推进。

## 运行与停止

- 观察台默认随运行启动（8792 起找空闲端口，启动行打印回连校验地址；`--no-viewer` 关闭）。
- 进度看 `state.json`（每窗 `knight`/`normal` 计数与目标）、`events.jsonl`、`timeline.jsonl`、`latest-*.png`；`recognition-*.json` 排错。
- 两窗独立推进互不阻塞；单窗异常只暂停该窗。用户中途手动辅助：识别回到已知画面即可接续，等待期间全程响应 STOP。
- 停止：说停或建 `<output>/STOP`；只终止本脚本，不杀 bridge、不退出游戏。
- 详见 [运行说明](references/operation.md)；离线验证结果见 [验证](references/validation.md)。

## 验证范围

51 项逻辑测试、25 张参考图 ×3 档回放全过 + 队员弹窗多尺度检测（960/850/680/615px 单弹窗、双弹窗、城内反例）、mock 三队员设备端到端（双队长各 1 侠士+1 普通、960/850/615 三种弹窗尺寸全靠脚本点准备、时序断言"准备先于进本"、181 点击合法、observe 零输入、STOP）。真机已验证：5 设备（3 台物理机）10 客户端不同大小 4:3 识别与操作。未宣称：更小窗口（<615px）的弹窗识别；队长设备兼任队员设备已有离线逻辑支持，仍需实机验证。

运行器默认开启逐窗口区域 OCR 缓存：仅在新截图的区域像素、尺寸、坐标与放大倍数完全一致时复用识别结果。点击前的新帧和移动后复核照常执行。配置 `ocr_cache: false` 可恢复原 OCR 管线；缓存只保留在本次运行内，不写入账号配置或证据图。离线耗时与限制见 [启动验证](../STARTUP-VALIDATION.md)。
